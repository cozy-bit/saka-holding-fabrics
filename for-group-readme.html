📁 2. Как устроен проект и правила стилей

Иерархия папок в `src/`:

src/
├── assets/                   # Фотографии и логотипы, разделенные по авторам
│   ├── shared/logos/         # Общие логотипы (Saka, Tortex, Eros)
│   ├── bakhtovar/            # Фото для главной, каталога и товара
│   ├── amirkhon/             # Аватар профиля, иконки калькулятора
│   ├── shukrullo/            # Фото фабрики, сертификаты, картинки новостей
│   └── ali/                  # Иллюстрации доставки, карта контактов
│
├── components/
│   ├── layout/               # Header, Footer, базовый Layout
│   ├── modals/               # CartModal, PriceListModal, CallbackModal
│   └── ui/                   # Общие кнопки (Button), инпуты (Input), бейджи (Badge)
│
├── pages/                    # Папки страниц (Home, About, Catalog, Delivery...)
├── context/                  # Глобальное состояние (корзина, модалки)
└── routes/                   # Настроенный роутер (AppRoutes.jsx)
📸 Где брать картинки: Все фотографии уже скачаны из Figma и лежат в папке src/assets/[ваше_имя]/[страница]/. Импортируйте их прямо в компонент:
import myImg from '../../assets/shukrullo/about/01-factory-main.png';

🎨 Правила стилизации для Шукрулло и Али (React + CSS Modules):

Чтобы вы могли спокойно учить чистый CSS и при этом ваши стили гарантированно не ломали страницы других ребят, мы используем CSS Modules (.module.css).

1
Вы пишете обычный чистый CSS в файле `.module.css`
Открываете, например, AboutPage.module.css и верстаете привычными свойствами: 
.container {
  max-width: 1200px;
  margin: 0 auto;
  padding: 40px 20px;
}

.title {
  font-size: 32px;
  font-weight: 700;
  color: var(--color-primary); /* Фирменный синий цвет Saka! */
}
2
Подключаете классы в JSX через объект `styles`
В файле страницы импортируете файл стилей:
import styles from './AboutPage.module.css';

export function AboutPage() {
  return (
    <div className={styles.container}>
      <h1 className={styles.title}>О компании</h1>
    </div>
  );
}
🐙 3. Пошаговая инструкция работы с Git и GitHub
⚠️ САМОЕ ГЛАВНОЕ ПРАВИЛО: Никто и никогда не пишет код напрямую в ветку main! Каждый создает свою ветку, пишет код там, заливает на GitHub и открывает Pull Request.
1
Склонировать проект (делается 1 раз в самом начале)
Откройте терминал в папке, где хотите сохранить проект:
git clone <ссылка-на-репозиторий-из-github>
cd saka-holding-fabrics
2
Установить библиотеки и запустить локальный сервер
Установите зависимости, которые мы уже настроили:
npm install
npm run dev
После этого перейдите по ссылке http://localhost:5173 в браузере. Вы увидите работающий сайт со всеми страницами!
3
Создать СВОЮ ветку под свою задачу
Перед тем как писать код, создайте свою личную ветку:
# Примеры названия веток:
git checkout -b feature/about-shukrullo
git checkout -b feature/delivery-ali
git checkout -b feature/catalog-bakhtovar
git checkout -b feature/calculator-amirkhon
4
Написание кода и сохранение (Commit)
Верстайте свою страницу в своей папке. Когда сделали часть работы, сохраните изменения:
git status                  # Посмотреть, какие файлы изменились
git add .                   # Добавить все свои изменения
git commit -m "feat: сверстал блок преимуществ о компании"   # Сделать коммит с понятным описанием
5
Отправить ветку на GitHub (Push)
Отправьте свою ветку на удаленный сервер:
git push origin <название-вашей-ветки>

# Например:
git push origin feature/about-shukrullo
6
Создать Pull Request (PR) на сайте GitHub
1. Зайдите на страницу репозитория на GitHub.
2. Наверху появится желтая плашка с кнопкой «Compare & pull request» — нажмите её.
3. Напишите кратко, что вы сделали (например, «Сверстал страницу О компании») и нажмите зеленую кнопку «Create pull request».
4. Скиньте ссылку на PR Амирхону или в чат команды на проверку!
7
Как обновить свою ветку, когда кто-то другой смержил код (Pull)
Чтобы забрать свежие обновления от других участников:
git checkout main          # Переключиться на main
git pull origin main       # Скачать последние обновления от команды
git checkout <ваша-ветка>   # Вернуться в свою ветку
git merge main             # Влить обновления в свою ветку
🛡️ 4. Золотые правила, чтобы не было конфликтов
  • ✔ Работайте только в своих файлах: Шукрулло меняет только src/pages/About, News, Article. Али — только Delivery, Contacts, PriceListModal.
  • ✔ Не трогайте общие файлы: Файлы AppRoutes.jsx, Layout.jsx, Header.jsx уже настроены. Если вам нужно что-то изменить глобально — согласуйте с Амирхоном.
  • ✔ Проверяйте сборку перед отправкой: Перед git push запустите в терминале команду npm run build. Если она проходит без красных ошибок — смело отправляйте!
